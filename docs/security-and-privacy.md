# Security & privacy — AI knowledge platform addendum

> Scope: the AI-memory features added by [implementation-plan.md](implementation-plan.md).
> This document **extends** — never overrides — [SECURITY.md](../SECURITY.md) (non-negotiable
> rules), [THREAT_MODEL.md](../THREAT_MODEL.md), and [ASSUMPTIONS.md](../ASSUMPTIONS.md).
> Any conflict resolves in favour of those documents.

## 1. Invariants inherited by every new feature

1. **Locked layers are absolute.** No new index, history record, retrieval pass, job, or health
   metric may read, count, or name anything in a locked layer.
2. **No decrypted private content on disk.** New persisted artifacts (`.strata/ai/*`, versions,
   prompt library, retrieval caches) either contain no private content (enforced by redaction,
   §2) or live inside the encrypted layer store (per-note versions of private notes).
3. **Consent pipeline is mandatory.** Remote calls: policy gate → explicit confirmation →
   privacy receipt. Mutations: operation plan → visual diff → human approval → snapshot-backed
   apply → undo. New features add *profiles* of this pipeline, never bypasses.
4. **Untrusted content is data.** Imported files, fetched URLs, transcripts, and pasted material
   are wrapped in neutralised `<source>` blocks; instructions inside them must not steer the
   model. The model has no tools and no autonomy: its output is a proposal validated against a
   closed schema and a selection constraint.
5. **Closed error enum, allowlist logging.** New services raise `StrataError` subtypes only;
   nothing new logs content, titles, or paths.

## 2. Redaction rules for persisted AI memory

Normative specification in [ai-memory-design.md](ai-memory-design.md) §3. Summary: any record
whose execution involved a private layer is persisted with `redacted=True` — content fields
(prompt, response, source object ids, plan summaries/details) emptied; metadata (provider, model,
tokens, counts, layer ids, timestamps) retained. Redaction happens inside `AIHistoryService` at
write time, so no caller can forget it. Verified by security tests that run private content
through the AI path and grep the raw history files.

## 3. New attack surfaces and their controls

| Surface (phase) | Risk | Control |
| --- | --- | --- |
| Persisted AI history (1) | Private content leakage to disk; history as surveillance of the user | Redaction (§2); `clear_history`; files stay inside the user-owned workspace; no telemetry |
| Live-request source blocks (1, fix) | Prompt injection via `</source>` breakout in note content | `render_source_block` (delimiter neutralisation + attribute escaping) now used on the request path, matching the export path |
| URL import (2) | SSRF, private-network probing, huge/hostile payloads | Scheme allowlist (`https`), DNS-rebind-safe private-range block (resolve-then-connect check), redirect refusal, size + time caps, content-type validation, content stored as untrusted capture |
| File import (2) | Malicious files, path traversal, decompression bombs | Existing `safe_filename`/`resolve_within`; size caps (64 MB attachment cap exists); imports never execute; MIME sniffing on import; PDFs/images processed only by explicit user action |
| Extraction/synthesis output (2, 4) | Model proposes destructive or out-of-scope changes; invented citations | Existing selection constraint + per-item approval + destructive-never-preapproved; citation ids validated against the actual context/retrieval trace — unknown ids reject the output |
| Retrieval (3) | Scope creep pulling notes the user didn't intend; embeddings as plaintext-equivalent (T-09) | Permission filter runs first; scope is explicit and displayed ("what you see is what gets sent" preserved); private-layer vectors in-memory only, destroyed on lock; per-layer embeddings policy enforced |
| Saved prompts (3) | Prompt files as an injection vector if shared/imported | Prompts are user-authored config, rendered into the *instruction* channel only after explicit user action; imported prompts flagged for review before first run |
| Conversation replay (3) | Old private context resent to a remote model without fresh consent | Replay re-evaluates the policy gate per turn against *current* layer states; locked-since-then content drops out |
| Background jobs (2+) | Unbounded resource use; partial writes | Cooperative cancel (exists), concurrency limits in `JobService`, idempotent payload ids, all mutations still via transactional apply |
| Embedded browser pane (8) | A second web view inside the app window, holding the user's sign-in cookies; a scraped page is hostile input; a page that reached the app origin would reach the bridge | Off by default (`settings.browser_control_enabled`); its own `QWebEngineProfile` — separate cookie jar, cache and storage path from the app profile, which stays `NoPersistentCookies`; **no `QWebChannel` installed on that page**, so nothing it loads has a channel to Python; navigation restricted to `http`/`https`, so `strata://` and `file://` are unreachable; clipboard, window.open, screen capture and fullscreen all off; extracted text stored as an untrusted capture and rendered as text, never markup; pane closed with the window. Residual: the cookie store is at-rest plaintext to an attacker with the disk, like any browser profile (T-34) |
| User scripts in the Qt pane (8) | Code the user supplies, injected into every page the pane opens, with the page's own privileges | **Empty by default**, one deliberate file choice each through a native picker, capped at 20. Injected into the main world on purpose — a script that cannot see the page is not a user script — and at the point its own `@run-at` asks for. It inherits the pane's boundary exactly as an extension does: no `QWebChannel`, no host object, no route to the workspace or a locked layer. A file that cannot be read is reported in the Research panel, not skipped. Residual: the same as any user script anywhere — it can read and exfiltrate what is in the pane. Stated plainly in the guide; a discretion decision, not a boundary |
| Host blocklist in the Qt pane (8) | A user-supplied list of hosts whose requests the pane refuses | Purely subtractive: it can stop a request, never add, rewrite or observe one. Matching is host-suffix on a label boundary, so `evil.com` cannot be made to catch `notevil.com`. Main-frame navigation is exempt, so the list cannot make the pane silently refuse to go where the user asked. Scoped to the research page's own interceptor, so the app's own view is unaffected by a research setting |
| Chrome backend (8) | A loopback debugging port is a read channel into every open tab, including logged-in ones; a compromised frontend could drive the browser | Not the default. Off with the same kill switch; port bound to `127.0.0.1` and non-loopback debugging addresses refused by the client; Strata-owned browser profile, so the everyday session is not exposed unless the user redirects `browser_profile_path`; reading is one tab at a time and user-initiated; the launched browser is terminated when the window closes. Residual: any process running as the user can drive an open debugging port (T-34) |
| Research filing (8) | An AI proposing edits to notes the user wrote, not only new pages | Targets restricted to the retrieved candidate shortlist *and* the ticked layers — an id that was never offered is dropped, not resolved; additions are `append_note`, never `update_note`, so nothing existing is rewritten; each appended block carries a visible provenance line naming the source and execution; the whole plan still goes through review → per-item approval → transactional apply → undo |
| Scheduled reviews (6) | Surprise AI runs / surprise spend | Manual-first; scheduling is local, opt-in, visible, and local-provider-only unless explicitly confirmed per schedule |
| Provider base-URL overrides (audit) | A provider the catalogue calls local ("Runs on this machine. Nothing leaves it.") pointed at a LAN or internet host, so a **local-only** layer is gated on a label while its plaintext goes elsewhere | Locality is recomputed from the endpoint in use, not read from the catalogue: `AIService.capabilities_for` clears `is_local` unless the base URL resolves to loopback (`app.domain.ai.is_local_endpoint`), and that single value feeds the policy gate, the routing preference, the privacy receipt and the UI badge. The setting itself is validated (`http(s)` only, host required, no embedded credentials), as is `relay_url`. Verified by `tests/security/test_provider_endpoint_locality.py` |
| Dev-server / environment variables (audit) | The main window's page carries the WebChannel; an env var that repoints it hands every bridge — notes, unlocked layers, settings, the browser — to whatever answers | A packaged build ignores `STRATA_DEV_SERVER` and is always `production` (so the developer tools cannot be switched onto the bridge page either); a source checkout accepts only a loopback `http(s)` URL. The page's allowance is compared by **origin**, not by string prefix — `startswith("http://localhost:5173")` also accepts `http://localhost:5173.attacker.example`. Verified by `tests/security/test_privileged_window_origin.py` |
| Collaboration presence (audit) | Awareness blobs went to the untrusted relay as plain JSON — display name, the note the peer had open, cursor offset — and unauthenticated, so the relay could invent collaborators | Presence is sealed under the LDK like every other blob (`TYPE_PRESENCE`, AAD binding layer, document *and peer id*, so a blob cannot be re-served in another peer's slot); anything that fails to open is dropped rather than displayed. Restores the ADR-0006 property: the relay sees sizes, timing and pseudonymous peer ids and nothing else. Verified by `tests/security/test_presence_sealing.py` |
| Relay server resource use (audit) | The self-hostable relay is unauthenticated by design and kept its log in memory without a ceiling: anyone who could reach it could fill the host | Bounded per channel and overall (`MAX_CHANNELS`, `MAX_CHANNEL_BYTES`, `MAX_PEERS_PER_CHANNEL`), refusing with `507` rather than evicting — a silently dropped CRDT update would leave a peer believing it had converged. Authentication in front of a public relay remains the deployment's job |

| `browser.get_status` / `launch` / `close_browser` | 8 | The first method that starts a process. `get_status` answers even when the feature is off (the UI must be able to say why it is unavailable) and leaks nothing but the configured paths the user typed; every other browser method raises `PermissionDeniedError` while `browser_control_enabled` is false. A refused call now answers on `blurEvent` instead of returning silently, so the UI can say why a press did nothing |
| `settings.update_settings` — endpoint validation | audit | The bridge already refused unknown keys; it did not check the *values* that name somewhere Strata sends data. `provider_base_urls` and `relay_url` are now validated at the settings boundary (`http(s)`, host required, no embedded credentials) and a rejected value never reaches disk. | Log redaction covers tracebacks and nested values | audit | `format_exc_info` renders an exception to text; it ran *after* the redactor, so every `logger.exception` — including the bridge's unhandled-error path — wrote absolute paths into `strata.log`. Verified end to end in `tests/security/test_log_redaction.py` |
| Log file growth | audit | The log had no rotation while this process logs from a 1.5 s capture-sweep timer and from every frontend console message — a long-lived install grew one unbounded file, and a log nobody can open is a log nobody can audit. A `<meta>` CSP is parsed by the document it sits in: it cannot govern a subresource and `frame-ancestors` is ignored there. The scheme handler now sends `Content-Security-Policy` (plus `X-Content-Type-Options` and `Referrer-Policy`) with every response, which is what the frontend comment already claimed |

## 5. Privacy controls roadmap

Users get, in order: clear AI history (1); per-layer AI policy editor UI, already modeled as
`LayerAIPolicy` (2); provider allowlist + URL-fetch kill-switch (2); retrieval exclusions
(`ai_readable_layer_ids` on lenses exists; per-note `ai: exclude` frontmatter added) (3);
conversation retention rules (3); redact-values pass for captures (7). Provider credentials
remain in the OS keychain (fails closed); model-training opt-out headers are sent where
providers support them (documented per provider, never claimed where unsupported).

## 6. Non-goals restated

Local malware and a compromised OS remain out of scope (THREAT_MODEL). AI memory does not make
Strata "zero-knowledge" — while unlocked, the app holds keys and plaintext in memory, and
public-layer history is plaintext on the user's own disk by design. We document leakage; we do
not market around it.

**Process concealment is a non-goal, and a refused one.** The system tray can hide Strata's
*window* from the taskbar (`minimize_to_tray`, off by default), but the *process* stays fully
visible to Task Manager and every other OS process tool. Hiding a process from the OS requires
kernel-level DKOM or API-hooking rootkit techniques; an app that shipped them would be
indistinguishable from malware, would be flagged as such by AV/EDR, and would betray the trust
a local-first encrypted workspace depends on. A request to hide the process — including via a
"run as a service" framing, which does not hide it either — is declined by design, not by
omission. `app/desktop/tray.py` states this at the top of the module so a future contributor
does not quietly add it.
